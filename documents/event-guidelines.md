# 📘 CODESTORM 2026 – Participant Guidelines

### November Edition | GDG on Campus – RIT Hassan

**Theme: Think. Create. Innovate. Build the Future.**

---

## 1. Introduction

Welcome to CODESTORM 2026 – November Edition!

These guidelines help participants understand the preparation process, project development expectations, and submission requirements.

All participants are expected to follow the instructions provided by the organizing team.

## 2. Before Participating

Participants should:

- Complete the official registration form.
- Read the selected challenge's problem statement.
- Understand the requirements and evaluation criteria.
- Choose individual or team participation as permitted.
- Join the official event communication group.
- Keep track of announcements from the organizers.

## 3. Challenge Selection

Participants can explore the following challenges:

### Challenge 01 – Website Building Challenge

Develop a professional website that provides meaningful information or solves a particular need.

Recommended preparation:
- Learn HTML, CSS, and JavaScript.
- Understand responsive web design.
- Plan the website structure.
- Prepare suitable images and content.
- Test the website on different devices.
- Deploy the completed website.

### Challenge 02 – Real-World Problem & Solution

Identify a real-world problem and create or propose a technology-based solution.

Recommended preparation:
- Observe problems in everyday life.
- Research existing solutions.
- Identify gaps and opportunities.
- Develop a practical solution.
- Select appropriate technologies.
- Prepare a clear explanation and demonstration.

## 4. Project Development Guidelines

### Planning

Before development:

1. Understand the problem.
2. Define the project objectives.
3. Identify the target users.
4. Plan the features.
5. Select the technology stack.
6. Divide tasks if participating as a team.

### Development

During development:

- Write clean and organized code.
- Use meaningful names for files and variables.
- Follow suitable coding practices.
- Test features regularly.
- Maintain a structured GitHub repository.
- Use external resources responsibly.

### Testing

Before submission:

- Check all important features.
- Test navigation and links.
- Verify responsive design.
- Fix major errors.
- Check the project on different browsers.
- Confirm that the live project is accessible.

## 5. Technology Recommendations

Participants may choose suitable technologies based on their project requirements.

| Area | Suggested Technologies |
|---|---|
| Frontend | HTML, CSS, JavaScript, React, Next.js |
| Backend | Node.js, Express, Python, Flask, Django |
| Database | MySQL, PostgreSQL, MongoDB, Firebase, Supabase |
| UI/UX | Figma, Canva |
| AI/ML | Python, TensorFlow, Scikit-learn |
| Version Control | Git, GitHub |
| Deployment | Vercel, Netlify, GitHub Pages |

These are recommendations, not mandatory technology choices.

## 6. GitHub Repository Guidelines

Every project repository should ideally contain:

- Project title and description.
- README documentation.
- Source code.
- Installation instructions.
- Technology stack.
- Screenshots or demo information.
- Credits and third-party resource references.

Ensure that the repository is accessible to the evaluation team.

## 7. Presentation Guidelines

Participants should be prepared to explain:

1. Project title.
2. Problem or purpose.
3. Proposed solution.
4. Technologies used.
5. Important features.
6. Development process.
7. Project demonstration.
8. Future improvements.

Keep the explanation clear, structured, and understandable.

## 8. Responsible Use of AI Tools

AI tools may be used to support learning and development.

Participants should:

- Understand AI-generated code.
- Verify generated information.
- Test generated solutions.
- Avoid submitting copied projects.
- Give appropriate credit where required.

## 9. Final Preparation Checklist

- [ ] Registration completed.
- [ ] Challenge selected.
- [ ] Problem statement understood.
- [ ] Project requirements reviewed.
- [ ] Project completed.
- [ ] Testing completed.
- [ ] GitHub repository prepared.
- [ ] Live demo verified, if applicable.
- [ ] Documentation prepared.
- [ ] Submission details checked.

## 10. Communication

Participants should follow official event announcements for:

- Event updates.
- Submission instructions.
- Important deadlines.
- Schedule changes.
- Evaluation information.
