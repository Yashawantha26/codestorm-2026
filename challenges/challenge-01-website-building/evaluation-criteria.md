# Challenge 01 – Website Building Challenge
## Official Evaluation Criteria

**Event:** CODESTORM 2026 – November Edition  
**Organizer:** GDG on Campus – RIT Hassan  
**Evaluation:** 100 Marks

## 1. Overview

Projects will be evaluated based on design quality, functionality, technical implementation, creativity, responsiveness, code quality, and presentation.

The evaluation aims to recognize websites that demonstrate practical problem-solving, innovation, and effective use of web technologies.

## 2. Mark Distribution

| Sl. No. | Evaluation Category | Maximum Marks |
|---|---|---:|
| 1 | UI/UX Design and Visual Appeal | 20 |

## 3. Detailed Evaluation

### 3.1 UI/UX Design and Visual Appeal – 20 Marks

Judging aspects:

- Overall website appearance and layout.
- Professional color combinations.
- Typography and readability.
- Consistent spacing and alignment.
- Visual hierarchy and navigation design.
- Appropriate use of images, icons, and animations.

### 3.2 Functionality and User Experience – 20 Marks

Judging aspects:

- Working navigation links.
- Functional buttons and interactive elements.
- Correct implementation of website features.
- Smooth and understandable user flow.
- Useful and meaningful functionality.
- Proper handling of forms and user inputs, where applicable.

### 3.3 Technical Implementation – 20 Marks

Judging aspects:

- Appropriate use of web technologies.
- Correct frontend implementation.
- Backend and database integration, where applicable.
- Proper use of APIs, where applicable.
- Error handling and overall stability.
- Successful deployment and accessibility.

### 3.4 Creativity and Innovation – 15 Marks

Judging aspects:

- Originality of the website idea.
- Innovative features and solutions.
- Creative presentation of information.
- Practical usefulness.
- Unique approach to the selected domain.

### 3.5 Responsive Design – 10 Marks

Judging aspects:

- Mobile compatibility.
- Tablet compatibility.
- Desktop layout.
- Proper image and content scaling.
- Readable text and accessible navigation across screen sizes.

### 3.6 Code Quality and Organization – 10 Marks

Judging aspects:

- Clean and readable code.
- Proper file and folder organization.
- Meaningful naming conventions.
- Reusable components or functions, where appropriate.
- Proper documentation.
- Public GitHub repository with a useful README.

### 3.7 Project Presentation – 5 Marks

Judging aspects:

- Clear explanation of the project.
- Understanding of technologies used.
- Explanation of important features.
- Ability to answer questions from judges.

## 5. Scoring Guidelines

Judges should award marks based on the quality and completeness of each category.

| Performance Level | General Description |
|---|---|
| Excellent | Outstanding quality, complete implementation, and strong execution. |
| Very Good | Strong implementation with minor improvements needed. |
| Good | Satisfactory implementation with some missing details. |
| Average | Basic implementation with noticeable limitations. |
| Needs Improvement | Incomplete or poorly implemented requirements. |

## 6. Tie-Breaking Considerations

If two or more projects receive the same total score, the organizers and judges may consider:

1. Functionality and User Experience.
2. Technical Implementation.
3. Creativity and Innovation.
4. UI/UX Design and Visual Appeal.

The final tie-breaking process will be handled by the evaluation team.

## 7. Important Notes

- All projects will be evaluated using the published criteria.
- Judges may inspect the deployed website and GitHub source code.
- Participants should be prepared to explain their implementation.
- Optional advanced features are not mandatory.
- The evaluation process and final decisions will be managed by the organizers.
